## 1. 시스템 구성

### 1-1. 물리 구성

과제 문서 기준, **고정 앵커 인프라 없이 지게차가 모바일 앵커로 기능**한다.
앵커 4대가 지게차 지붕의 한 플라스틱 케이스에 들어가므로 배열 개구는 최대 50cm다.
커스텀 PCB 없이 현재 구성(라즈베리파이 + DWM3001CDK ×4)이 그대로 케이싱된다.

| 역할 | 보드 | 앱 | 비고 |
|---|---|---|---|
| **마스터** | RX1 | LISTENER + `SYNCM 1` | 앵커 + 시각 기준 겸용 |
| 앵커 | RX2, RX3, RX4 | LISTENER | 수신 전용 |
| 태그 | 별도 | SIMPLETX | MAC 0x0002~ |
| 호스트 | Raspberry Pi 4 | — | USB 4채널, 엣지 연산 |

```
앵커 좌표 (지게차 지붕 기준, m)
    RX2(0.0, 0.0)      RX3(0.4, 0.0)
    RX1(0.0, -0.4)     RX4(0.4, -0.4)
     └ 마스터
```

### 1-2. 왜 앵커가 시각 기준을 겸하는가

- 무선 동기화에는 **송신원이 필요**하다. 앵커는 전부 수신 전용이므로 누군가 쏴야 한다.
- 별도 비콘 유닛을 두면 제안서의 "앵커 4대" 구성이 깨진다.
- 앵커 1대가 겸하면 보드 수가 유지되고, **그 보드의 동기 오차가 0**이 되어
  정확도가 오히려 개선된다 (외부 비콘 6.34cm → 2.24~4.45cm).
- 마스터는 Pi 에 USB 직결이므로 자기 송신 시각을 UART 로 바로 보고할 수 있다.
  → UWB 페이로드에 실을 필요가 없어 프레임이 11바이트로 짧아진다.

## 2. 데이터 흐름

```
RX1 ──[동기 프레임 송신]──▶ RX2,3,4 수신
 │                              │
 └─[TXTS: seq 0x...]──▶ Pi ◀────┘ [LSTN ... MAC 0x0001]
                         │
태그 ──[blink]──▶ RX1~4 ─┘        [LSTN ... MAC 0x0002]
                         │
                         ▼
              시계 모델 → TDoA → 좌표
```

### 로그 3종

```
[RX1] TXTS: 3A 0x08423AF215                                    마스터 송신 시각 T
[RX2] JS..{"LSTN":[41,88,3A,26,00,FF,FF,01,00,xx,xx],"TS40":..} 동기 수신 (11바이트)
[RX3] JS..{"LSTN":[41,88,7C,26,00,FF,FF,02,00,..],"TS40":..}    태그 수신 (17바이트)
```

MAC(인덱스 7~8)으로 동기/태그를 구분한다. `TS40` 은 40비트 수신 타임스탬프,
`O` 는 클럭 오프셋(pphm), `rsl`/`fsl` 은 신호 세기다.

## 3. 동기화 원리

### 3-1. 핵심 — 타임스탬프를 소프트웨어가 읽지 않는다

`RX_TIME` / `TX_TIME` 은 프리앰블이 안테나를 지나는 순간 DW3000 하드웨어가
직접 래치한다. MCU 도 OS 도 관여하지 않으므로 15.65ps 분해능에 지터가 없다.
UART 는 그 숫자를 **나중에 보고**할 때만 쓰이고, 보고가 늦어도 값은 변하지 않는다.

이것이 CLI TSYNC 방식과의 근본적 차이다 (5장 참조).

### 3-2. 수식

```
offset_i = R_i^sync − T                       (i = RX2,3,4)
         = b_i + (a_i−1)·T + a_i·τ_i1

  b_i  : 위상 오프셋 (임의값)
  a_i  : 클럭 속도비 (1 + 수 ppm)
  τ_i1 : RX1 → 앵커 i 비행시간 (기구 고정 상수)

태그 패킷:
  corrected_1 = R_1^tag                       마스터는 기준이라 보정 없음
  corrected_i = R_i^tag − offset_i^pred

  TDoA_1i   = corrected_i − corrected_1
  r_i − r_1 = c·U·(TDoA_1i + τ_i1)
```

### 3-3. 10사이클 스무딩 — 단순 평균 금지

10사이클(약 100ms) 동안 2.7ppm 드리프트면 275ns(17,500 카운트)가 밀린다.
따라서 **먼저 회귀로 기울기를 뽑고 그 직선으로 외삽**해야 한다.
포럼의 AndyA 원문 "after allowing for drift rates" 가 이 뜻이다.

창 크기는 실측상 **10이 최적**이다.

| 창 | RX2 | RX3 | RX4 |
|---|---|---|---|
| 5 | 5.76 cm | 5.86 cm | 7.79 cm |
| **10** | **5.30** | **6.07** | **6.83** |
| 20 | 6.75 | 8.76 | 7.30 |
| 40 | 14.58 | 11.93 | 13.40 |

창을 키우면 나빠지는 이유는 클럭이 수십 초 단위로 **비선형 드리프트**하기
때문이다 (보드 예열 추정).

### 3-4. 무결성 검증 — `O` 필드 교차 확인

타임스탬프 회귀 기울기와 `O` 필드(반송파 주파수 오프셋)는 완전히 다른 경로로
얻는 값인데 소수점 둘째 자리까지 일치한다.

| RX | 회귀 (ppm) | `O` 필드 (ppm) |
|---|---|---|
| RX2 | −0.6284 | 0.5700 |
| RX3 | −1.7063 | 1.7000 |
| RX4 | +1.0946 | −1.1000 |

부호가 반대인 것은 `O` 필드의 정의 방향 차이다.
**파이프라인을 고칠 때마다 이 두 값이 여전히 맞는지 먼저 확인할 것.**

## 4. 좌표 산출

### 4-1. TDoA + 거리 1개 → 삼변측량

TDoA 는 거리 *차이*만 준다. 기준 앵커의 절대 거리 r₁ 이 하나 있으면
나머지 거리가 전부 복원되어 평범한 삼변측량이 된다.

```
r_i = r_1 + c·U·TDoA_1i

|p − a_i|² = r_i²  에서 1번 식을 빼면 |p|² 이 소거되어 p 에 대해 선형:

2p·(a_i − a_1) = |a_i|² − |a_1|² − r_i² + r_1²
```

미지수 2개에 식 3개 → 최소제곱 닫힌 해. 반복 없음.

### 4-2. TWR 이 필요한 이유 — 실측 근거

개구 50cm 배열은 **삼변측량기가 아니라 방향 탐지기**다.

가정한 r₁ 을 바꿔가며 확인한 결과:

| 가정 r₁ | 해의 거리 | 방위 | 방위 산포 |
|---|---|---|---|
| 0.5 m | 1.06 m | −167.1° | 6.13° |
| 1.0 m | 1.82 m | −163.9° | 5.62° |
| 2.0 m | 3.36 m | −161.6° | 5.08° |
| 5.0 m | 7.97 m | −160.1° | 4.75° |

**가정을 10배 바꿔도 방위는 7° 안, 거리는 8배 변한다.**
거리를 미지수로 두고 자기일관 해를 찾으면 20m 상한까지 발산한다.

TDoA 단독 오차 타원:

| 거리 | 단축(방위) | 장축(거리) | 비율 |
|---|---|---|---|
| 1 m | 10 cm | 155 cm | 16 : 1 |
| 3 m | 28 cm | 43.9 m | 158 : 1 |

TWR 거리(10cm) 1개를 병합하면 타원이 거의 원이 되고 3m 까지 30cm 이내가 된다.

```
TDoA → 방위 (7.3°)        TWR → 거리 (~10cm)        둘 합쳐 (x, y)
```

**TWR 은 앵커 4대 전부와 할 필요 없다.** 1대면 거리가 잡히고 나머지는 배열
TDoA 가 방위를 담당한다. 다중 태그 트래픽 부담도 줄어든다.

### 4-3. 방식 B 구현 상태 (2026.08.28)

**태그 펌웨어 완료.** 태그가 마스터 동기 프레임을 수신하여 자기 시계를
마스터 시계에 묶을 재료를 보고한다.

```
태그 프레임 23바이트
  idx 10~14  자기 blink 송신 시각 t1      (TX_TIME, 40비트)
  idx 15     들은 동기 프레임 SeqNum
  idx 16~20  그 동기 수신 시각 t4          (RX_TIME, 40비트)
```

| 실측 항목 | 결과 |
|---|---|
| 동기 수신 성공률 | **100%** (258개 중 257회 갱신) |
| `sync_seq` 전진 | **+4 규칙적** — blink 1주기에 동기 4개, 그중 첫 번째를 잡음 |
| 외삽 구간 | 동기 1주기 이내 → 거리 오차 예산 **3cm** |

**기법 명칭**: 무선 동기화 앵커 배열 TDoA + SS-TWR 하이브리드.
동기 프레임 하나가 ① 앵커 동기화 ② TWR 개시 ③ 태그 시계 기준을 겸하므로
추가 공중 트래픽이 0이고 태그 수에 무관하게 확장된다.

**핵심 함정**: `dwt_setrxtimeout()` 을 쓰면 `t4` 가 전부 0이 된다. 단위가
문서 추정과 달라 타임아웃이 즉시 걸린다. **`dwt_setrxtimeout(0)` 으로 끄고
소프트웨어 가드(약 4000회 ≈ 28ms)만 쓰는 것이 해법이었다.**

`dwt_readsysstatuslo()` 가 SPI 트랜잭션(1회 5~10µs)이라는 점도 중요하다.
가드를 300만으로 잡으면 blink 주기가 21초가 된다.

### 4-4. 안테나 지연 보정 — 미검증 상수

수식을 끝까지 전개하면 상쇄되지 않는 항이 하나 남는다.

```
dt_i = (τ_i^tag − τ_1^tag) + (d_master^tx − d_1^rx)
                              └────────────────┘
                     마스터의 송신 − 수신 안테나 지연
```

앵커 i 의 수신 안테나 지연은 동기 수신과 태그 수신에 똑같이 들어가 상쇄되지만,
**마스터 자신의 TX/RX 지연 차이**는 세 앵커 모두에 같은 값으로 더해진다.

태그 참값 (−1.3, −0.2) 기준으로 역산한 값:

```
δ = −29.6 cm = −63.1 카운트 = −0.99 ns
보정 전 방위 편향 +25.9°  →  보정 후 잔여 편향 16.2 cm
```

⚠️ **이 값은 검증되지 않았다.** 태그 1곳의 참값에 맞춰 역산한 것이라 반드시
맞아떨어진다. 진짜 상수인지 확인하려면 **태그를 2~3곳, 특히 방위가 반대편인
위치에 놓고** 같은 δ 가 나오는지 봐야 한다.

## 5. 기각된 접근과 근거

### 5-1. CLI TSYNC (호스트 시각 기준)

라즈베리파이 시각을 공통 기준으로 삼아 각 앵커의 UWB 카운터를 매핑하는 방식.
2026.08.17 실측으로 **세 군데에서 독립적으로 막힘**을 확인했다.

| 항목 | 필요 | 실제 | 배율 |
|---|---|---|---|
| 매핑 정확도 (200회 평균) | 0.3 m | 34 km | 11만 |
| 타임스탬프 분해능 | 1.0 ns | 4.0064 ns | 4 |
| 재동기 주기 | 370 µs | 22 ms | 59 |

**결정적 이유**: `SYS_TIME` 레지스터는 40비트 카운터의 **상위 32비트만 노출**한다.
로그에서 `TS40` 은 10자리, `TSYNC` 는 8자리 — 이 2자리가 1.2m다.
전송 지터를 완전히 제거해도 이 바닥이 남는다.

잔차의 1차 자기상관이 ≈0(백색잡음)이라 평균으로 줄이려면 4.1×10¹² 샘플
(약 7.6만 년)이 필요하다.

**GPIO 동시 트리거도 안 된다**: UART 지터는 없어지지만 인터럽트 지연 + SPI 읽기
(수 µs) + SYS_TIME 양자화(4ns)가 남는다. **소프트웨어가 시계를 읽는 구조는
어떻게 개선해도 못 넘는다.**

### 5-2. 유선 SYNC 핀

DW3000 의 SYNC 는 GPIO7 인데 DWM3001C 모듈이 이 핀을 외부로 노출하지 않는다
(데이터시트 Rev F Table 2). DK 회로도에도 SYNC 네트가 없다.

### 5-3. 예약 송신 (`dwt_setdelayedtrxtime`)

`DX_TIME` 은 상위 32비트만 지정 가능(4.0064ns 단위)이라 실제 송신 시각이
예약값과 어긋나고, 그 차이(scheduling quantization)를 별도로 계산해 전송해야 한다.
포럼 질문자 almeidas88 이 이 경로에서 "오프셋이 32비트 전 범위에 걸쳐 랜덤"이라는
문제로 막혀 있었다.

**우리 방식은 실제로 찍힌 값을 읽어서 쓰므로 이 함정이 없다.**
실측 로그에서 송신 타임스탬프 하위 9비트가 항상 21로 고정된 것이 확인되는데
(512카운트 = 8.01ns 격자 + 안테나 지연 21), 격자에 걸려도 **값을 알고 있으므로
오차가 아니다.**

### 5-4. UART 921600

nRF52833 에서 실제 레이트가 937,500bps(오차 1.7%)라 **간헐적으로 문자가 누락**된다.
완전히 깨지지 않고 99% 맞아서 눈으로는 멀쩡해 보이는 것이 위험하다.
`TS40` 자릿수가 조용히 8자리가 되는 식으로 데이터가 오염된다.
**230400 고정할 것** (실측 오차 0.6%, 자릿수 검사 29,810개 전수 통과).

### 5-5. SDK 의 FiRa `OWR_UL_TDOA`

세션은 ACTIVE 되나 `fira_ranging_info` 의 `timestamp_ns` 가
`[NOT IMPLEMENTED]` 로 문서화되어 있어 동작하지 않는다.
Qorvo 직원 답변도 "QM33 SDK does not support TDoA use cases" 로 일치한다.

## 6. 구현 파일

### 6-1. 펌웨어 (Qorvo DW3_QM33_SDK 1.1.1)

| 파일 | 변경 |
|---|---|
| `HAL/Src/nrfx/HAL_uart.c` | 보드레이트 230400 |
| `listener/task_listener.c` | **동기 마스터 겸용**, TS40 40비트 출력 |
| `listener/listener_fn.c` | `SYNCM` 서브커맨드 |
| `simpletx/simpletx.c` | 태그. Source MAC 0x0002, **방식 B 동기 수신 (2026.08.28)** |
| `common/cmd/cmd_fn.c` | `SETAPP SIMPLETX` |
| `project_CLI.cmake` | `USB_ENABLE` 제거 (J9 UART 단독) |

**동기 마스터 구현의 핵심**

```c
wr = qsignal_wait(listenerTask.signal, &signal_value, SYNC_WAIT_MS);
if (g_sync_master) {
    if (wr != QERR_SUCCESS || ++rx_since_sync >= SYNC_EVERY_N) {
        rx_since_sync = 0;
        sync_tx_once();     /* forcetrxoff → starttx → readtxtimestamp
                               → rxenable, qirq_lock 으로 보호 */
    }
}
```

- 원래 `qsignal_wait` 이 `WAIT_FOREVER` 라 **수신이 없으면 태스크가 깨어나지 않았다.**
  타임아웃을 주어야 동기가 끊기지 않는다.
- 별도 스레드를 만들면 `error_handler` 로 보드가 정지하는 문제가 있어
  ListenerTask 안에서 처리한다. 이 태스크에서 SPI 를 쓰는 것은 검증되어 있다.
- 송신 간격은 규칙적일 필요가 없다. **실제 송신 시각을 그대로 보고**하므로.
- TXFRS 대기 루프에 반드시 가드를 둘 것. 없으면 고우선순위 태스크가 무한
  스핀하여 CLI 무반응 → 워치독 리셋으로 이어진다 (`simpletx` 에서 실제 발생).

| `sprintf` 추가 | 시작 직후 리셋, `Current App: NONE` | 스택 2048 초과 |
| `diag_printf`/`port_tx_msg` | 출력 없음 | **SimpleTX 태스크에서 동작 안 함.** 진단은 프레임 페이로드로 |
| 플래시 후 태그 정지 | 태그 프레임 0개 | NVM 이 덮어써짐. 매번 `SETAPP`+`SAVE` |
| `SIMPLETX` 중 CLI 잠김 | 명령 불가 | 고우선순위 태스크 특성. **원래부터의 정상 현상** |

⚠️ **인터럽트 제거는 미시도.** `simpletx_process_start()` 의
`qplatform_uwb_interrupt_enable()` 이 남아 있다. 현재 동작하므로 유지했으나,
수신 문제 재발 시 `dwt_isr` 이 상태 비트를 선점하는지 확인할 것.

## 7. 호스트 파싱에서 반드시 지킬 것

개발 중 실제로 겪은 버그들이다. 재발하면 좌표가 통째로 망가진다.

| 항목 | 안 지키면 |
|---|---|
| **마스터 TX/RX 타임스탬프는 같은 unwrap 누적기 공유** | 스케일 2.6초 어긋남 |
| **unwrap 은 부호 있는 차분** (`d=(v−prev)%2^40; if d>2^39: d−=2^40`) | 로그 순서 뒤바뀔 때 가짜 wrap → 범위 45.8초(실제 27초) |
| **SeqNum 은 unwrap 후 256 배수 보정** | 앵커별 수신 시작이 달라 2.61초 어긋난 짝 |
| **바퀴 보정은 반드시 256의 배수** | 두 앵커는 같은 seq 열을 보므로 그 외의 값은 오류 |
| **앵커 간 정렬은 패킷 신원 기준** | 탈락 항목이 달라 인덱스가 다른 패킷 지시 |
| **버퍼 제거는 `append` 전에** | deque 가 꽉 차면 append 시 자동으로 빠지므로, 뒤에 지우면 아직 필요한 항목을 지움 |
| **정렬은 ±256 배수 후보를 훑을 것** | 슬레이브 g 가 마스터보다 앞서면 같은 g 조회는 영원히 실패 |
| **정렬은 여러 번 같은 값일 때 확정** | 초기 잡음에 잘못 고정되면 영구히 좌표 0 |
| 태그 `t1`/`t4` 도 40비트 unwrap 필요 | 17.2초마다 감김 |
| 태그 시계 모델도 `sync_seq` 로 `TXTS` 와 짝 | seq 8비트 순환 주의 |

## 9. 알려진 한계와 남은 작업

### 9-1. 검증되지 않은 것

| 항목 | 현재 | 필요 |
|---|---|---|
| **δ = −29.6 cm** | 태그 1곳에서 역산 | 2~3곳, 특히 방위 반대편에서 재확인 |
| **거리 r₁** | `--range` 로 주입 | TWR 구현 |
| 이상치 (P95 71.6cm) | 원인 미규명 | `rsl` 필터로 개선되는지 확인 |
| 태그 참값 | "대략 (−1.3, −0.2)" | cm 단위 실측 |

`uwb_realtime.py` 는 **보정 전 원시 dt 를 CSV 에 저장**하므로, δ 가 확정되면
`--replay` 로 기존 데이터를 전부 재계산할 수 있다.

### 9-2. 구조적 한계

- **개구 50cm** → 거리는 TDoA 로 결정 불가. TWR 필수.
- **"30cm @ 몇 m" 미확정** → TWR 병합 시 3m 까지 성립, 그 이상은 물리적 한계.
  비투윈랩·교수님과 합의 필요.
- **앵커 4대 고정, 추가 불가** → 제안서 구성 유지.
- **커스텀 PCB 없음** → 공통 클럭·SYNC 배선 불가. 무선 동기화가 유일 경로.
